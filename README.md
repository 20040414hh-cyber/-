# 信息图形设计研究知识库

本仓库用于持续研究信息图形（Information Graphics / Infographics）的数据逻辑、统计图形转译、视觉编码、信息架构与视觉叙事。它不是单纯的图表素材库，也不把信息图形等同于数据可视化仪表盘。

## 知识库结构

- **01-信息图形数据逻辑/**：五种基础数据组织逻辑的概念定义与设计方法。此目录只保存文字研究文档，不保存案例图片。
- **02-信息图形类型案例/**：按视觉表达类型整理案例研究、设计规律与方法总结。案例图片及其来源信息归档在本目录或其子目录。

## 研究原则

- **先识别信息关系，再选择图形形式**：图形必须服务于数据关系和叙事目的。
- **区分数据准确性与视觉表达**：视觉编码可以强化识别，但不得歪曲数量、比例、空间或时间关系。
- **把统计图形当作表达语法，而不是最终成品**：信息图形还需要符号系统、图文层级、版式组织与叙事路径。
- **区分事实、解释和设计判断**：每条案例结论标明证据来源与可信程度。
- **以案例驱动迭代**：新案例进入后，先记录观察，再比较既有案例，最后决定是否修订通用原则。

## 案例研究工作流

1. 收录原始案例图，记录作者／机构、标题、来源 URL、发布日期、画面尺寸及版权信息。
2. 描述画面可见事实，不先写主观评价。
3. 拆解数据结构、统计方法、视觉编码、信息架构和叙事顺序。
4. 标注有效策略、局限与可迁移方法。
5. 与同类案例交叉比较；只有获得多个案例或明确理论依据支持时，才将观察提升为通用原则。
6. 更新对应案例文档，并在 01 目录中维护指向相关案例研究的相对链接。

## 版本与证据标记

- **[通用原则]**：经过多案例比较或可靠方法论支持的稳定结论。
- **[案例观察]**：仅适用于某一具体案例的可见特征。
- **[待验证假设]**：有解释力但尚缺少足够案例支持的判断。
- **[待补充案例图]**：当前尚无用户提供的原图，不代表已完成图像分析。

每次重要修订应在对应文档末尾的「更新记录」中记录日期、变更内容、依据案例和影响范围。

## 目录维护约定

- 当前固定使用现有两个内容目录。后续补充优先修改现有 Markdown，不因新增案例、主题或图片而创建新文件夹或新文档；只有明确提出结构调整时才改变目录。
- 案例图片直接放在“02-信息图形类型案例”现有目录层级，不为单个案例新增子文件夹。建议图片名包含案例 ID、主题、来源简称和年份。
- “01-信息图形数据逻辑”只保存方法论文字，不嵌入图片；通过相对 Markdown 链接引用第二目录中的案例文档或图片。
- 新案例优先追加到现有三篇案例类型文档。若案例跨越多个类型，在主归类文档完整分析，其他文档只做交叉链接，避免重复维护。

## 两部分文档的关系

“数据逻辑”回答信息之间的关系是什么；“案例类型”回答这些关系如何被视觉化表达。二者不是一一对应关系：同一案例可以同时包含时间、层级、编目或地理逻辑，也可以混合列表、时间轴和统计图形。分类时分别标注主导逻辑与辅助逻辑，不要把版式形式误认为数据结构。

## 案例结论的证据层级

1. **可见事实**：原图中可直接确认的标题、颜色、图形类型、标签和版式。
2. **来源事实**：作者说明、数据源或出版页面明确提供的内容。
3. **分析推断**：对设计意图、阅读路径、受众或视觉效果的解释，必须写成推断而非事实。
4. **设计建议**：从案例迁移到新项目的做法，应注明适用条件，不等于原作者意图。

## 更新流程与质量门槛

每次补充案例后，依次完成：登记来源与授权信息 → 记录可见事实 → 拆解五个维度 → 标注证据层级 → 与既有案例对照 → 决定是否修订原则 → 更新日期和影响范围 → 检查相对链接。提交前检查：没有新增目录、没有重复分析、没有失效链接、没有把推断写成事实、没有遗漏数据口径。
