# 信息图形设计研究知识库

本仓库用于持续研究信息图形（Information Graphics / Infographics）的数据逻辑、统计图形转译、视觉编码、信息架构与视觉叙事。它不是单纯的图表素材库，也不把信息图形等同于数据可视化仪表盘。

## 知识库结构

- **01-信息图形数据逻辑/**：五种基础数据组织逻辑的概念定义与设计方法。此目录只保存文字研究文档，不保存案例图片。
- **02-信息图形类型案例/**：按视觉表达类型整理案例研究、设计规律与方法总结。案例图片及其来源信息归档在本目录或其子目录。

## 研究原则

- **先识别信息关系，再选择图形形式**：图形必须服务于数据关系和叙事目的。
- **区分数据准确性与视觉表达**：视觉编码可以强化识别，但不得歪曲数量、比例、空间或时间关系。
- **把统计图形当作表达语法，而不是最终成品**：信息图形还需要符号系统、图文层级、版式组织与叙事路径。
- **区分事实、解释和设计判断**：每条案例结论标明证据来源与可信程度。
- **以案例驱动迭代**：新案例进入后，先记录观察，再比较既有案例，最后决定是否修订通用原则。

## 案例研究工作流

1. 收录原始案例图，记录作者／机构、标题、来源 URL、发布日期、画面尺寸及版权信息。
2. 描述画面可见事实，不先写主观评价。
3. 拆解数据结构、统计方法、视觉编码、信息架构和叙事顺序。
4. 标注有效策略、局限与可迁移方法。
5. 与同类案例交叉比较；只有获得多个案例或明确理论依据支持时，才将观察提升为通用原则。
6. 更新对应案例文档，并在 01 目录中维护指向相关案例研究的相对链接。

## 版本与证据标记

- **[通用原则]**：经过多案例比较或可靠方法论支持的稳定结论。
- **[案例观察]**：仅适用于某一具体案例的可见特征。
- **[待验证假设]**：有解释力但尚缺少足够案例支持的判断。
- **[待补充案例图]**：当前尚无用户提供的原图，不代表已完成图像分析。

每次重要修订应在对应文档末尾的「更新记录」中记录日期、变更内容、依据案例和影响范围。

## 两部分文档的关系

“数据逻辑”回答信息之间的关系是什么；“案例类型”回答这些关系如何被视觉化表达。二者不是一一对应关系：同一案例可以同时包含时间、层级、编目或地理逻辑，也可以混合列表、时间轴和统计图形。分类时分别标注主导逻辑与辅助逻辑，不要把版式形式误认为数据结构。

## 案例结论的证据层级

1. **可见事实**：原图中可直接确认的标题、颜色、图形类型、标签和版式。
2. **来源事实**：作者说明、数据源或出版页面明确提供的内容。
3. **分析推断**：对设计意图、阅读路径、受众或视觉效果的解释，必须写成推断而非事实。
4. **设计建议**：从案例迁移到新项目的做法，应注明适用条件，不等于原作者意图。

### 一、两种分类维度必须分开

课程第 2 页提出五种以数据架构逻辑为依据的类型：编年型、层级型、编目型、字母表型、地理图型（PDF 第 2 页）。这五类回答的是**信息之间按什么关系组织**。

课程第 22—38 页又展示多种常见视觉表现类型：混合型、文字／列表型、时间轴型、示意图型、流程图型、比较型、地标型、图片式、层级型、单一图表型、可视化文字、解剖图式、可视化简历、手稿型、编年＋编目混合型和 3D 信息图形。它们回答的是**信息最终以什么形式呈现**。

因此，数据逻辑与视觉形式不是一一对应关系。同一张图可以同时具有“编年＋编目”数据逻辑，并采用环形时间轴、流向图和地图等视觉形式；分类时应分别记录主导数据逻辑、辅助数据逻辑和主要视觉形式，不把版式外观误当成数据结构。

### 三、选题与设计流程补充

课程第 40 页提出三项匹配原则：信息编码形式应与内容特点匹配；预期读者的背景知识应与可视化形式的运作机制匹配；受众越专业，图表可以采用越专业的表达。第 42 页进一步提示通过阅读路径、主题识别、图中现象与参数、强调部分的变化，以及客观信息和作者评论的区分来检查理解情况。

将课程流程整理为本项目的工作步骤（PDF 第 43 页）：

1. **数据收集与清洗**：核对来源、定义、单位、时间／空间范围和缺失值。
2. **数据集与结构搭建**：先确定对象、字段、关系和主要问题。
3. **视觉编码与版式排布**：再选择图表、符号、色彩、字体、网格和阅读路径。
4. **数据关联与内容呈现**：检查不同模块之间是否存在真实关系，并通过注释解释关联。

设计顺序应先结构、后形式。课程第 70 页强调先考虑数据结构，再考虑修饰；检查修饰是否超过实质内容；不要在确定组织方式前先决定风格，也不要因为预设读者看不懂而删减必要数据。

### 四、视觉表达的平衡与质量判断

课程第 48—53 页用多组对照提醒设计者：抽象与具象、实用与修饰、致密与稀疏、多维与单维、创新与通用、简洁与冗余之间都存在取舍。这些不是简单的优劣排名，应由信息任务、数据复杂度、读者背景和媒介尺寸共同决定。

课程第 54—57 页强调简洁、高效和避免图表垃圾；第 55 页介绍“数据／油墨比”，可作为检查装饰冗余的启发式指标：

\[
数据／油墨比 = \frac{用于编码数据的视觉墨迹}{图表全部视觉墨迹}
\]

该比值用于提醒设计者检查非必要线条、装饰图标、背景和重复标注，不应机械追求数值最大化；必要的标题、图例、坐标和注释仍然承担理解功能。第 56—57 页对图表垃圾的讨论与第 67—68 页的观点共同指向：**美化应增强理解，而不是替代数据组织；应简化表达形式，而不是无依据地简化信息内容。**

课程第 69 页提出分层阅读思路：先给出数据概要作为入口，再提供尽可能充分的内部信息，并用逻辑顺序和导航帮助读者按需深入。可将其作为长幅信息图形、专题展板和复杂图表的架构检查方法。
